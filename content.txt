## 1. Giới Thiệu

### 1.1. Bối Cảnh Dự Án

Trong bối cảnh số hóa ngày càng phát triển, các doanh nghiệp cần các giải pháp quản lý nhân sự hiệu quả để tối ưu hóa nguồn lực con người. Dự án HR-Cloud Platform được phát triển nhằm đáp ứng nhu cầu này bằng cách xây dựng một nền tảng đám mây toàn diện cho quản lý nhân sự. Dự án sử dụng kiến trúc microservices để đảm bảo tính mở rộng, bảo mật và dễ bảo trì.

Dự án HR-Cloud Platform là một hệ thống quản lý nhân sự dựa trên đám mây, bao gồm các chức năng chính như xác thực người dùng, quản lý sơ đồ tổ chức, quản lý nghỉ phép và tuyển dụng. Hệ thống được thiết kế với kiến trúc microservices, sử dụng các công nghệ hiện đại như Spring Boot cho backend, React cho frontend, và Docker để containerization.

### 1.2. Mục Tiêu Dự Án

Mục tiêu chính của dự án là xây dựng một nền tảng HR toàn diện với các mục tiêu cụ thể sau:

- Phát triển hệ thống xác thực bảo mật sử dụng JWT
- Triển khai sơ đồ tổ chức với cấu trúc cây phân cấp
- Quản lý nghỉ phép với stored procedure đảm bảo tính toàn vẹn dữ liệu
- Hệ thống tuyển dụng với khả năng tìm kiếm nâng cao sử dụng MongoDB
- Giao diện người dùng thân thiện với React
- Containerization toàn bộ hệ thống với Docker

### 1.3. Phạm Vi Dự Án

Dự án bao gồm 5 services chính:

1. Identity Service: Xử lý xác thực và phân quyền
2. Organization Service: Quản lý sơ đồ tổ chức
3. Leave Service: Quản lý nghỉ phép
4. Recruitment Service: Quản lý tuyển dụng
5. Frontend Service: Giao diện người dùng

Hệ thống sử dụng SQL Server cho dữ liệu HR truyền thống và MongoDB cho dữ liệu tuyển dụng linh hoạt.

## 2. Phân Tích Yêu Cầu

### 2.1. Yêu Cầu Chức Năng

Hệ thống HR-Cloud Platform cần đáp ứng các yêu cầu chức năng sau:

- **Xác thực người dùng:** Đăng nhập, đăng ký, xác thực JWT
- **Quản lý tổ chức:** Xem sơ đồ tổ chức dạng cây, CRUD nhân viên
- **Quản lý nghỉ phép:** Gửi yêu cầu nghỉ phép, phê duyệt, tra cứu lịch sử
- **Tuyển dụng:** Quản lý ứng viên, tìm kiếm theo kỹ năng, kinh nghiệm

### 2.2. Yêu Cầu Phi Chức Năng

- **Hiệu suất:** Thời gian phản hồi < 2 giây cho các API
- **Bảo mật:** Mã hóa mật khẩu, JWT token, CORS
- **Khả năng mở rộng:** Kiến trúc microservices
- **Tính sẵn sàng:** Containerization với Docker

### 2.3. Phân Tích Use Case

Dưới đây là chi tiết các use case chính của hệ thống HR-Cloud Platform:

**Use Case 1: Đăng nhập hệ thống**
- **Actor:** Người dùng (Nhân viên, HR Manager, Admin)
- **Mô tả:** Người dùng nhập username và password, hệ thống xác thực thông tin và trả về JWT token để sử dụng cho các API tiếp theo.
- **Pre-conditions:** Người dùng đã có tài khoản trong hệ thống.
- **Post-conditions:** Người dùng nhận được JWT token và được chuyển hướng đến Dashboard.
- **Alternative Flow:** Nếu sai thông tin đăng nhập, hiển thị thông báo lỗi.

**Use Case 2: Xem sơ đồ tổ chức**
- **Actor:** Nhân viên HR hoặc Manager
- **Mô tả:** Hiển thị sơ đồ tổ chức dạng cây phân cấp, cho phép xem thông tin chi tiết từng nhân viên.
- **Pre-conditions:** Người dùng đã đăng nhập và có quyền truy cập.
- **Post-conditions:** Hiển thị tree structure với thông tin nhân viên.
- **Alternative Flow:** Nếu không có quyền, hiển thị thông báo lỗi.

**Use Case 3: Gửi yêu cầu nghỉ phép**
- **Actor:** Nhân viên
- **Mô tả:** Nhân viên chọn số ngày nghỉ, hệ thống kiểm tra LeaveBalance còn đủ không, nếu đủ thì tạo record trong LeaveRecords.
- **Pre-conditions:** Nhân viên đã đăng nhập, có LeaveBalance > 0.
- **Post-conditions:** LeaveBalance được trừ, record được lưu.
- **Alternative Flow:** Nếu không đủ ngày phép, hiển thị thông báo lỗi.

**Use Case 4: Tìm kiếm ứng viên**
- **Actor:** HR Manager
- **Mô tả:** HR nhập tiêu chí tìm kiếm (kỹ năng, kinh nghiệm, vị trí), hệ thống trả về danh sách ứng viên phù hợp từ MongoDB.
- **Pre-conditions:** HR đã đăng nhập với quyền quản lý tuyển dụng.
- **Post-conditions:** Hiển thị danh sách ứng viên với thông tin chi tiết.
- **Alternative Flow:** Nếu không tìm thấy, hiển thị danh sách trống.

**Use Case 5: Thêm nhân viên mới**
- **Actor:** Admin hoặc HR Manager
- **Mô tả:** Nhập thông tin nhân viên mới, cập nhật sơ đồ tổ chức.
- **Pre-conditions:** Có quyền admin.
- **Post-conditions:** Nhân viên được thêm vào database, sơ đồ tổ chức cập nhật.

**Use Case 6: Phê duyệt nghỉ phép**
- **Actor:** Manager
- **Mô tả:** Manager xem danh sách yêu cầu nghỉ phép, phê duyệt hoặc từ chối.
- **Pre-conditions:** Có yêu cầu pending.
- **Post-conditions:** Status cập nhật, nếu phê duyệt thì gọi stored procedure.

## 3. Thiết Kế Hệ Thống

### 3.1. Kiến Trúc Tổng Thể

Hệ thống HR-Cloud Platform được thiết kế theo kiến trúc microservices, một approach hiện đại cho việc phát triển ứng dụng phân tán. Kiến trúc này mang lại nhiều lợi ích như khả năng mở rộng độc lập từng service, dễ bảo trì và triển khai.

#### 3.1.1. Tổng Quan Kiến Trúc
- **Frontend Service:** Giao diện người dùng duy nhất, chạy trên port 80 với Nginx, phục vụ React SPA.
- **Identity Service:** Xử lý authentication và authorization, port 8081.
- **Organization Service:** Quản lý sơ đồ tổ chức, port 8082.
- **Leave Service:** Quản lý nghỉ phép, port 8083.
- **Recruitment Service:** Quản lý tuyển dụng, port 8084.
- **Databases:** SQL Server cho dữ liệu quan hệ, MongoDB cho dữ liệu NoSQL.

#### 3.1.2. Luồng Xử Lý Chính
1. User truy cập frontend qua browser.
2. Frontend gọi API đến Identity Service để authenticate.
3. Sau khi có JWT, frontend gọi các API khác với Bearer token.
4. Mỗi service truy cập database riêng hoặc dùng API Gateway (tương lai).

#### 3.1.3. Lợi Ích Của Microservices
- **Scalability:** Mỗi service có thể scale độc lập dựa trên load.
- **Technology Diversity:** Có thể dùng ngôn ngữ khác nhau cho từng service.
- **Fault Isolation:** Lỗi ở một service không ảnh hưởng toàn hệ thống.
- **Team Autonomy:** Nhóm khác nhau có thể phát triển từng service.

#### 3.1.4. Communication Patterns
- **Synchronous:** RESTful APIs giữa frontend và backend services.
- **Asynchronous:** Có thể thêm message queue cho future enhancements.
- **Database per Service:** Mỗi service có database riêng để tránh coupling.

#### 3.1.5. Containerization Với Docker
Tất cả services được đóng gói trong Docker containers, orchestrated bởi Docker Compose. Điều này đảm bảo consistency giữa development và production environments.

### 3.2. Thiết Kế Cơ Sở Dữ Liệu

**SQL Server Schema:**
- Bảng Staff: ID, Name, ManagerID, Salary, LeaveBalance
- Bảng LeaveRecords: ID, StaffID, Days, Date

**MongoDB Schema:**
- Collection Candidates: skills[], projects[], workExperiences[], certifications[]

### 3.3. Thiết Kế Microservices

Mỗi service có cấu trúc chuẩn:
- Controller: Xử lý HTTP requests
- Service: Logic nghiệp vụ
- Repository: Truy cập dữ liệu
- Entity/DTO: Mô hình dữ liệu

### 3.4. Thiết Kế Giao Diện Người Dùng

Frontend sử dụng React với:
- Dark theme premium
- Responsive design
- Pages: Login, Dashboard, Org Chart, Leave, Recruitment

### 3.5. Bảo Mật Và Xác Thực

- JWT authentication với HS256
- BCrypt password hashing
- Stateless security
- CORS configuration

- Container: Docker, Docker Compose

### 4.2. Triển Khai Identity Service

Identity Service là trái tim của hệ thống bảo mật, sử dụng Spring Security framework để implement JWT authentication.

#### 4.2.1. Cấu Trúc Service
- **Controller:** AuthController với endpoints /login, /register, /me
- **Service:** AuthService xử lý logic đăng ký, đăng nhập
- **Repository:** UserRepository truy cập bảng Users trong SQL Server
- **Security:** JwtUtil, JwtAuthFilter, SecurityConfig

#### 4.2.2. JWT Implementation
JwtUtil class sử dụng HS256 algorithm để generate và validate tokens:

```java
@Component
public class JwtUtil {
    private String secret = "hrcloud-secret-key";
    
    public String generateToken(String username) {
        return Jwts.builder()
                .setSubject(username)
                .setIssuedAt(new Date())
                .setExpiration(new Date(System.currentTimeMillis() + 1000 * 60 * 60 * 10))
                .signWith(SignatureAlgorithm.HS256, secret)
                .compact();
    }
    
    public String extractUsername(String token) {
        return Jwts.parser().setSigningKey(secret).parseClaimsJws(token).getBody().getSubject();
    }
}
```

#### 4.2.3. Security Configuration
SecurityConfig cấu hình stateless authentication:

```java
@Configuration
@EnableWebSecurity
public class SecurityConfig extends WebSecurityConfigurerAdapter {
    
    @Autowired
    private JwtAuthFilter jwtAuthFilter;
    
    @Override
    protected void configure(HttpSecurity http) throws Exception {
        http.csrf().disable()
            .authorizeRequests()
            .antMatchers("/api/auth/**").permitAll()
            .anyRequest().authenticated()
            .and()
            .sessionManagement().sessionCreationPolicy(SessionCreationPolicy.STATELESS)
            .and()
            .addFilterBefore(jwtAuthFilter, UsernamePasswordAuthenticationFilter.class);
    }
    
    @Bean
    public PasswordEncoder passwordEncoder() {
        return new BCryptPasswordEncoder();
    }
}
```

#### 4.2.4. Authentication Flow
1. User gửi POST /api/auth/login với username/password
2. AuthService validate credentials
3. Nếu thành công, generate JWT token
4. Trả về token cho frontend
5. Frontend lưu token trong localStorage
6. Các API tiếp theo gửi token trong Authorization header

#### 4.2.5. CORS Configuration
Để cho phép frontend gọi API từ domain khác:

```java
@Configuration
public class CorsConfig {
    @Bean
    public CorsFilter corsFilter() {
        UrlBasedCorsConfigurationSource source = new UrlBasedCorsConfigurationSource();
        CorsConfiguration config = new CorsConfiguration();
        config.setAllowCredentials(true);
        config.addAllowedOrigin("http://localhost:3000");
        config.addAllowedHeader("*");
        config.addAllowedMethod("*");
        source.registerCorsConfiguration("/**", config);
        return new CorsFilter(source);
    }
}
```

### 4.3. Triển Khai Organization Service

Sử dụng Recursive CTE để truy vấn sơ đồ tổ chức:

```sql
WITH OrgChart AS (
    SELECT ID, Name, ManagerID, Salary, LeaveBalance, 0 AS Level
    FROM Staff WHERE ManagerID IS NULL
    UNION ALL
    SELECT s.ID, s.Name, s.ManagerID, s.Salary, s.LeaveBalance, o.Level + 1
    FROM Staff s JOIN OrgChart o ON s.ManagerID = o.ID
)
SELECT * FROM OrgChart ORDER BY Level, ManagerID, ID
```

### 4.5. Triển Khai Recruitment Service

### 7.3. Học Hỏi Và Kinh Nghiệm

Qua quá trình phát triển dự án HR-Cloud Platform, nhóm đã học được nhiều kinh nghiệm quý báu trong việc xây dựng hệ thống microservices.

#### 7.3.1. Kinh Nghiệm Về Microservices
- **Service Boundaries:** Việc xác định ranh giới giữa các services rất quan trọng. Ban đầu nhóm gặp khó khăn trong việc quyết định Recruitment Service nên dùng SQL hay NoSQL, nhưng MongoDB đã chứng minh phù hợp với dữ liệu linh hoạt.
- **Inter-service Communication:** RESTful APIs đơn giản nhưng hiệu quả. Trong tương lai, có thể cân nhắc gRPC cho performance cao hơn.
- **Data Consistency:** Việc sử dụng multiple databases (SQL + NoSQL) đòi hỏi careful design để tránh inconsistency.

#### 7.3.2. Kinh Nghiệm Về Bảo Mật
- **JWT Implementation:** Học được cách implement stateless authentication đúng cách, tránh common pitfalls như token không expire.
- **Password Security:** Sử dụng BCrypt thay vì MD5, nhận thức về importance của salt và work factor.
- **CORS Issues:** Gặp nhiều vấn đề với CORS trong development, học được cách configure properly.

#### 7.3.3. Kinh Nghiệm Về Database Design
- **Recursive CTE:** Kỹ thuật này rất powerful cho hierarchical data như org chart, nhưng cần optimize để tránh performance issues với large datasets.
- **Stored Procedures:** Đảm bảo atomicity cho complex business logic như leave approval.
- **MongoDB Aggregation:** Pipeline approach rất flexible cho complex queries, nhưng cần index properly.

#### 7.3.4. Kinh Nghiệm Về Frontend Development
- **React State Management:** AuthContext pattern hiệu quả cho global state, nhưng cần careful với re-renders.
- **API Integration:** Axios interceptors giúp centralize authentication logic.
- **Responsive Design:** CSS variables system giúp maintain consistent theming.

#### 7.3.5. Kinh Nghiệm Về DevOps
- **Docker:** Containerization giúp environment consistency, nhưng cần optimize image sizes.
- **Orchestration:** Docker Compose đơn giản nhưng powerful cho local development.
- **Version Control:** Git branching strategy quan trọng cho team collaboration.

#### 7.3.6. Bài Học Từ Challenges
- **Debugging Distributed Systems:** Khó khăn hơn monolithic apps, cần good logging và monitoring.
- **Testing Microservices:** Integration testing phức tạp hơn, cần mock services.
- **Deployment:** Rolling updates và zero-downtime deployment cần plan carefully.

#### 7.3.7. Skills Phát Triển
- **Technical Skills:** Spring Boot, React, Docker, JWT, MongoDB, SQL Server
- **Soft Skills:** Team collaboration, problem-solving, time management
- **Best Practices:** Code reviews, documentation, testing-driven development

Những kinh nghiệm này sẽ rất hữu ích cho các dự án tương lai, đặc biệt là trong việc xây dựng scalable web applications.
